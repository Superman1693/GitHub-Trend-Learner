# 每日热点邮件模板

> **用途**：每日热点解读的邮件正文模板，由 OrchestratorAgent 在聚合完成后套用。
> **设计依据**：`design.md` §12。邮件正文过长会被客户端截断，因此采用「正文放核心 + 附件放全文」。

---

## 邮件头

| 字段 | 取值 |
| --- | --- |
| 主题 | `GitHub 今日热点解读 · <YYYY-MM-DD>` |
| 收件人 | `<从配置读取，不硬编码在模板中>` |
| 附件 | `<YYYY-MM-DD>-github-trend.md`（当日完整六模块文档） |

## 降级情况下的正文补充

| 情况 | 在正文末尾追加 |
| --- | --- |
| 部分仓库解析失败 | `⚠️ 今日有 <n> 个仓库解析失败：<仓库名>（原因：<原因>）。其余内容不受影响。` |
| 使用了降级数据源 | `ℹ️ 今日热门榜单为主数据源不可用，已降级使用 Search API，榜单口径可能与官方 trending 略有差异。` |
| 存在未达标模块 | `⚠️ 以下内容未通过质量终审，已标注：<模块名>（<问题>）` |
| 邮件发送重试成功 | 无需说明，正常投递 |
| 邮件发送失败已归档 | 由系统另行提示，不写进正文 |

---

## 投递规则

1. 生成 `FinalDoc` 后按本模板组装。
2. 发送失败重试 **≤3 次**。
3. 仍失败则写入 `outputs/YYYY-MM-DD/`，并提示用户手动取用，**保证内容不丢失**。

---

## 写作约束（继承 `global.md` §1）

- 正文必须可独立阅读，不能依赖附件。
- 全程大白话，术语首次出现必须解释。
- 禁止套话；每句话携带可验证信息。
- 数据来源与获取时间必须标注（Req1.6）。
